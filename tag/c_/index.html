    C#中的抽象方法、覆寫與介面

    C# 畢竟也是物件導向程式，依然有物件導向的特性，所以也會有類別、物件、繼承、多型、多載跟覆寫的能力，一般最常使用到的就是物件(Object)跟類別(Class)，其次會用到繼承，最後寫方法時才會用到所謂的多型、多載跟覆寫的功能，簡單說一下這三個：

    • 覆寫(Override)：相同物件，相同函式名可以有不同的程式碼運作。
    • 多載(Overload)：相同函式名可以有不同的參數輸入型別、樣式與數量。
    • 多型(Polymorphism)：一個類別可以有不同的形態，父類別是子類別的通用格式，而子類別又可以利用覆寫跟參數變更來達到跟父類別相似卻又完全不同的樣子，以達到多型的特色，完成多型，其中一定少不了繼承的幫助。

    AutoResetEvent 的原理

    AutoResetEvent 是一種針對執行緒的同步方式，也就是在這個執行緒做一個類似「紅綠燈」的訊號，讓執行緒在主執行緒或本身的執行緒遇到這件事情後就立刻停止，直到通行訊號出現，算是一種變相的同步方式。我們就來看一下這個簡單的程式：

    using System;
using System.Threading;
using System.Threading.Tasks;

namespace structtest
{
    class Program
    {

        static int sec = 0;
        static AutoResetEvent autoResetEvent = new AutoResetEvent(false);
        static void Main(string[] args)
        {

            Thread TrDll = new Thread(countse);
            TrDll.IsBackground = true;
            TrDll.Start();

            autoResetEvent.WaitOne(15000);
            Console.WriteLine("Press any key to exit...");
            Console.ReadKey();
        }

        static void countse()
        {
            while(true)
            {
                Thread.Sleep(1000);
                sec++;
                Console.WriteLine($"sec: {sec}");
                if (sec >= 10)
                {
                    //autoResetEvent.Set();
                    break;
                }
            }
        }
    }

}

    PipeServer介紹

    什麼是 PipeServer?

    PipeServer 又被稱為是管道伺服器，是一種在本機系統上可以跨進程溝通的一種橋梁，也就是進程間通信(IPC, Inter-Process Communication)跟 Window Message 有異曲同工之妙，只是一個是針對進程，一個是針對視窗而已，適用的場合是在同台機器上的進程間通信。

    PipeServer 的特性與優缺點

    • 做法跟一般的 TCP 連線一樣，建立伺服與客戶端，並在此建立多進程互動
    • 有分為匿名(Anonymous)和具名(Named)兩種，前者主要處理父子視窗，後者處理跨進程溝通
    • 資料主要以字節流(bytes)形式進行傳輸
    • 本地進程間的通信延遲低，不需要網路介面
    • 無法使用網路通信
    • 可以使用非同步，但使用者太多還是有機會造成管道阻塞

    C# 的資料繫結

    什麼是資料繫結?

    資料繫結(Data Binding)是一種讓資料跟頁面連結再一起的方式，當參數變動的時候，會利用通知來通知頁面做變化，這部分在很多的前端或Native原生介面常常會出現這種東西，不過大多數都只會記得這種設計架構，他其實就是MVVM

    MVVM

    MVVM 是一種設計模式，可以類比於之前網路的MVC設計模式，而MVVM的模型主要以這三個為主：

    • Model：資料格式與資料處理層，往往跟後端與底層有著強連結，也是制定資料格式的地方，不需要處理任何界面問題。
    • View：也就是頁面。
    • View-Model：介於View與Model之間的橋樑，主要負責介面的互動根與Model資料索取的相關函式都算是，這個模組主要就是要解耦介面與資料，以方便做單元測試

    WPF的Converter

    什麼是轉換器(Converter)?

    轉換器(Converter)是WPF在xaml的一種工具之一，他主要是將原本不符合放在這個控制項上的參數轉換成控制項可以接手的參數，說直白就是在做一種資料轉換跟清洗的觀念，其實在資料繫結或是東西出來後你要轉換也是能達到相同的效果，那這樣為什麼要去使用它呢?

    資料邏輯與業務邏輯

    一般來說，一個頁面的會呈現的資料有很多種，我們可以把它分成兩大類，分別是跟：

    • 資料邏輯：也就是資料上的單純相互轉換，例如當我的亮度(整數)大於或小於多少的時候，我必須在我的介面上顯示亮度為高，我就必須將亮度(整數)轉成字串「高」，這樣才可以，這就是一般的資料轉換。
    • 業務邏輯：也就是資料與介面互動屬性的互相轉換，例如當我的亮度(整數)大於或小於多少的時候，我必須在我的介面上顯示一個紅色的驚嘆號來明顯表示，這時候我就必須讓Icon的Visibility(可視)顯示為True來顯示，這個就跟資料的顯示不同，他是根據資料改變其互動屬性，那就不是單純的資料轉換而已。
